# 2. 固定出口（可选）

下文命令都在技能根目录执行。先做完 [01-path-mac-clash.md](01-path-mac-clash.md)。这一页不是默认路径。

## 适用谁

已经能用订阅稳定工作，并且确实需要「同一个出口地址；一条路坏了换另一条路，地址不变」。

## 先问

- 你是不是只是觉得订阅偶尔会换节点？那留在 01。Fallback 在你选的几个节点之间换，地址可以变，会话可能重连。这不是故障。
- 你是否已经有静态 ISP 或同类固定地址账号，并且供应商条款允许你这样用？没有就不要为了这一页新买。选择标准见 [07-buying.md](07-buying.md)。
- 这个 AI 服务在你所在地区是否官方支持？不支持则停止。

## 目标

`AI-EXIT` 的成员变成同一账号上的几条路径：经不同前置节点，再加一条不经前置的直连。健康检查失败时换下一条，出口地址保持为你记下的那个。

这样做是为了连接稳定、长会话不被换地址打断，以及单位域名仍然直连。

## 前置

- 01 的 pass 已经满足。
- 你自己的固定出口账号：主机、端口、用户名、密码。只在本机脚本里填。
- 订阅里至少两个还能用的节点名，用作前置。名字以客户端当前显示为准。

## 附加约束

只用订阅的人不用遵守这两条：

1. 约定流量走这个出口，不把 `AI-EXIT` 临时切到别的组。
2. AI 客户端还连着的时候不要重载或退出 Clash，避免会话中断后出口变掉。改配置前先退出客户端。

## 步骤

1. `[Agent需确认]` 再做一次 [00-diagnose.md](00-diagnose.md) 里的备份。
2. `[用户UI]` 编辑扩展脚本：
   - `MODE` 改为 `"fixed-exit"`。
   - `ISP.port` 写成真实端口。`0` 会拒绝加载。
   - `ISP.server`、用户名、密码换成你的账号。不要把服务商端口编进节点名。脚本使用 `ISP-via1`、`ISP-via2`、`ISP-direct`。
   - `HOPS` 写成订阅里前置节点的显示名。
   - 仍然只启用你要用的 `AI_SERVICES`。
3. `[用户UI]` 退出 AI 客户端，重新激活订阅。
4. `[用户UI]` 确认模式仍是 Rule，TUN 仍开着。
5. `[Agent只读]` 把你从供应商控制台或一次成功探测里看到的地址记在自己的笔记里，然后：

```bash
EXPECTED_IP='你的固定出口地址' ./scripts/net-check.sh
```

不要把这个地址提交到仓库，也不要贴到聊天。

## 验证

- pass：没有 FAIL；`trace(proxy)` 的地址等于 `EXPECTED_IP`；组类型是 Fallback；至少一个成员延迟成功。
- fail：地址不相等、组不存在、探测无响应，或全部成员失败。
- 两条 trace 地址不一致时，先看是不是 TUN 没接住，不要直接换一个出口。

## 常见坑

- 订阅更新后前置节点改名，`dialer-proxy` 指向已经不存在的名字，整组超时。处理：对照新名字改 `HOPS`，退出客户端后再激活。不要为了先连上，把组切到一个随便的节点并当成修好。
- 端口仍是 `0`，或主机名仍含 `REPLACE_ME`。脚本会拒绝加载，运行时保持旧配置。
- 前置节点本身不通。Fallback 会尝试下一条；全部失败时看供应商状态，而不是改规则去绕过单位网络。

## 回滚

`[用户UI]` 把 `MODE` 改回 `"subscription"`，恢复原来的 `SUB_NODES`，退出客户端后重新激活。或者用备份覆盖 profiles 再激活。紧急情况走 [troubleshooting.md](troubleshooting.md)。
