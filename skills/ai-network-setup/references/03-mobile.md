# 3. 手机

下文命令都在技能根目录执行。Android 没有步骤。

## Android

当前未覆盖。不要把 iPhone 的界面或配置文件套到 Android 上。见仓库 `docs/ROADMAP.md`。

## 适用谁

iPhone，希望和 Mac 使用同一套分组思路。公司手机要先问 MDM 允不允许安装 Shadowrocket。不允许就停在这一页，不要想办法绕过设备管理。

## 先问

- 只是已有订阅，想稳定：用下面的界面步骤，**不要**导入模板。
- 已经在 Mac 上做了固定出口，手机也要同一个地址：才使用模板。
- 不在这里改整部手机的系统 IPv6。模板里的 `ipv6 = false` 只影响这份 App 配置。

## 目标

AI 相关域名走名为 `AI-EXIT` 的策略组。其余流量走你指定的普通节点或直连。凭据只留在手机上。

## 前置

- 已安装的 Shadowrocket。
- 一份你有权使用的订阅。固定出口还要你自己的账号。

## 步骤：只有订阅

全部是 `[用户UI]`。

1. 在 App 里添加订阅。链接不要发到电脑上的仓库或聊天。
2. 新建策略组，名字 `AI-EXIT`，类型用 Fallback（或 App 里的故障切换）。
3. 放进 2 到 3 个订阅节点。名字以 App 里显示的为准。
4. 给你实际使用的服务域名加规则，指向 `AI-EXIT`。不用的域名不要抄示例。
5. 单位域名指向 DIRECT。
6. 全局路由选「配置」。启用前看一眼节点列表里没有占位符。

## 步骤：固定出口（可选）

先在 Mac 上完成 [02-fixed-exit.md](02-fixed-exit.md)，再决定手机要不要同一地址。

1. `[用户UI]` 复制 `templates/shadowrocket.conf` 到手机之前，在电脑上替换占位符。前置节点整行换成真实节点定义，类型不一定是 socks5。所有端口现在是 `1`，必须改掉。
2. `[Agent只读]` 在技能根目录检查：

```bash
grep -n REPLACE_ME templates/shadowrocket.conf && echo '仍有占位符，不要导入'
```

有输出就不要导入。

3. `[用户UI]` 用「从文件导入」。导入后先打开配置详情，确认没有 `REPLACE_ME`、端口不是 1、策略组名字是 `AI-EXIT`，再启用。
4. 若 App 报 `udp-relay` 或 `tfo` 无法识别，删掉这两个参数后重新导入。不要改成非法的 `policy-regex-filter` 写法。

## 验证

`[用户UI]` 用 Safari 打开 `https://1.1.1.1/cdn-cgi/trace`。

- pass（只有订阅）：能打开，有 `ip=`。地址可以随 Fallback 变化。
- pass（固定出口）：`ip=` 等于你记下的固定出口地址。
- fail：页面打不开，或固定出口模式下地址不是你记下的那个。导入后配置里仍能看到 `REPLACE_ME` 也是 fail，先停用这份配置。

## 常见坑

- 把模板当成订阅用户的必经步骤。只有订阅时，在界面里建组就够了。
- 前置节点写成「等于某个订阅名」而不是一条完整节点定义。那样导入会失败，或保存后无法连接。
- 只在一台设备上改了规则，另一台的节点名已经变了。

## 回滚

`[用户UI]` 切回导入前的配置，或直接关闭 Shadowrocket。不要为了回退去改 MDM。
